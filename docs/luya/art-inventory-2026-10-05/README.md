## 展示混乱的具体来源

1. **同一人物有两种环境叙事。** 从本轮源图像素观察，经典鹿芽以暖色便利店、近距离招呼和直接互动为主；生活插画以明亮家居、做事或独处为主。衣着发色大体延续，机位、情境和人物尺度明显变化。下面是视觉判断，尚未让用户选择主视觉方向。
2. **构图规格混用。** 经典图通常3:4，等待图接近9:16，生活图4:3；房间同时存在3:2和3:4。contain＋模糊延展保留完整画面，但主体占屏比例仍有差异。经典人物带完整实景背景且没有Alpha透明层，不能直接作为独立人物叠在房间上。
3. **名称和实际状态语义错位。** `action-wave`用于“有些兴奋”；`action-waiting`用于“有些在意”，对应mood为angry；`expression-soft`用于“安静陪着”，对应sad。图像是动作／姿态，文案是互动状态，容易让用户把画面解读成不同含义。
4. **房间出现不同制作语言。** 原图人物为漫画插画，空房间接近写实；5类小摆件由代码几何图形绘制。它们的纹理、阴影和空间透视没有统一。房间背景内已有书、灯、家具，叠加摆件并非对背景家具逐件替换。
5. **记忆存在多套成品形式。** 单幅插画、空白对话框方格漫画、带排版文字的竖版漫画并存；当前已存记忆无visualUri时还会复用竖版漫画，画中固定情节可能与具体记忆文本不同。源码已注明示例／预置背景，但视觉本身仍有叙事暗示。
6. **版本、宣传、历史证据容易被误当成同一个“当前版本”。** `characters/v2`是人物套图版本，`luya-art-v2`只是房间竖版批次，人物生活图仍在art-v1。宣传站概念图、旧验收截图、现行源码具有不同更新节奏。旧文档关于装饰“总会注入”的描述也已不符合当前无调用的源码。

## 检查与资料缺口

- 本轮 `npx tsc --noEmit` 通过；`npm run verify:visual-assets`通过（90个检查条目＋角色注册表）。完整日志保存为 `visual-assets.log`。
- 现有视觉检查的扫描根没有 `assets/luya-art-v1`、`assets/luya-art-v2`，因此上述90项不能代表这7张新图被覆盖。本轮盘点额外用sharp实际解码60张应用源图和3张网站图并生成预览，读取尺寸与哈希；未修改既有检查规则。
- 37个镜像哈希一致；盘点生成后复核60张原图哈希与清单一致。
- 图册的分类、搜索、放大在浏览器检查；鹿芽源图已逐张对照缩略总览。图册嵌入的7张应用截图来自上轮2026-10-05验收，明确标为历史证据。本轮没有重新运行Expo或真机，不据此确认当前iPhone画面。
- 切片脚本 `scripts/extract-style-assets.py`指向 `design/figma/exports`，当前该目录无源板文件，13张切片仍在；缺少原板会影响今后重新切图。
- 鹿芽第一批5图有prompts和manifest；房间第二批2图有README与SHA，但没有同结构的机器清单。现有人物／记忆素材有资源注册表，未见逐图同结构生成提示词档案。
- 假设“已有”指项目内可编辑源图及静态网站资源；iPhone私有存档、用户自定义上传图、生成工具外部缓存未扫描。未将“无源码入口”理解为可删除，存档仍可能保存旧图URI。
