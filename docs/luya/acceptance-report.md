# 鹿芽 v1.0 开发验证与逐项验收记录

本轮已完成主要实现、自动化回归、有限真实模型测试与 Web 界面检查，但**尚不能判定 118 项用户验收全部通过，也不据此宣告可发布**。仍需在用户的旧数据副本及目标设备验证重启、通知、各状态素材和完整交互流程；L 组 10 项全部留给用户判断。

记录日期：2026-09-30（Asia/Shanghai）。代码：当前本地工作树，人物定义 schema v2，运行数据 schema v1，应用 package 版本 1.5.0；没有为本次报告创建提交，不能用已有 HEAD 代表全部未提交实现。范围以 [原始逐项清单](source/acceptance.md) 为准，准确计数 **118 项**：A8、B8、C8、D10、E10、F8、G8、H8、I10、J20、K10、L10。下表每个编号独立一行，不把相近要求合并成通过结论。

## 已有证据与边界

- [工程整链日志](evidence/engineering.log)：`npm run verify` 完成；10 个测试文件通过、1 个按设计跳过，**78 个测试通过、1 个真实模型开关测试跳过**。TypeScript、零警告 ESLint、聊天顺序/恢复、debug-now、90 项素材、中央资源表、v1.5 与工程硬化检查通过。跳过项不计作通过；实际联网模型测试另有证据。
- [真实模型审阅](evidence/model-review.md) / [原始响应与 Prompt](evidence/model-scenarios.json)：17 组、**59 轮**实际请求。Provider DeepSeek，请求 `deepseek-chat`；最近 44 轮返回 `deepseek-flash`，早期 15 轮未记录 resolvedModel。六场景、身份/边界及 20 轮讨论是有限样本；原失败输出保留，`REFLECTION_RETEST` 记录修复后回顾复测。模型样本“通过”只指该批样本的开发审查。各组保留执行当时的 Prompt；追加修复后没有据此证明旧组全部在最终代码上重跑，发布前应全量回归最终版本。
- [纯迁移前后对照](evidence/migration-comparison.json)：合成 fixture 的 135 条记忆、145 篇日记、140 条关系事件、纪念日、原关系/情绪、用户 Prompt 哈希保持一致，其他三类角色不变且重复迁移幂等；不等于已在用户真机数据库完成升级。
- [14/30 日回放](evidence/life-replay.json)：15/31 个检查点，连续计算与 JSON 重启哈希一致，离线补算 0 次模型请求；两个回放均通过。报告生成时核对其中四份源码 SHA-256 与当前文件一致。回放使用合成隔离数据，不证明真实设备重启，也不是模型连续生活体验。
- [Web 导出日志](evidence/web-export.log) 与截图见下方索引。已独立查看卡片、改写后来源和撤销重载截图：能看到候选卡、用户修正版、来源和已撤销分区。截图证明这些状态实际渲染；没有逐步操作记录的按钮或模型行为仍留待复测。
- 理解卡的 Web 自动回复使用仅监听本机的 `luya-ui-fixture`，每条带“UI 测试用模拟回复”标识；只证明按钮、消息来源和持久化接线，**不作为真实模型人设验收**。不读取或污染用户生产聊天。
- 当前仅支持时间向前推进。调试时间早于运行记录时保留存储并禁止把未来状态说成过去事实；恢复至最新记录之后再验收。

状态含义：**自动化通过**指对应断言已执行；**源码复核**仅证明实现路径存在；**真实模型有限样本通过**仅指所列响应；**Web 操作已验证**仅指隔离测试来源的实际页面操作；所有状态均不替代用户的“通过/失败/阻塞”勾选。本表没有把“实现存在”与“整条 UAT 通过”等同。
